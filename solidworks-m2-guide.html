Before You Begin

Compatibility Reality Check

SolidWorks has no native macOS version and officially supports only x86-64 Windows. On an M2 Mac, it runs through two translation layers: VMware Fusion runs Windows 11 ARM, and Windows ARM then emulates x86 for SolidWorks itself. Know the trade-offs before you start the install.

Step 01

Install VMware Fusion Pro

VMware Fusion Pro is free for personal use, but Broadcom's portal is genuinely difficult to navigate and has a hidden requirement that blocks downloads until your account is fully set up. Follow the steps below exactly — the "No data found" error means your account profile is incomplete, not that Fusion is unavailable.

Part 1 — Complete your Broadcom account profile (required)
⛔
"No data found" means your profile is incomplete. Broadcom requires a Trade Compliance form to be submitted before any downloads are unlocked. Without it, every download page shows "No data found" regardless of the URL you use.
  1. Go to support.broadcom.com and create a free account (or sign in). Use your real name and a permanent email address.
  2. After signing in, click your account icon (top right) → Edit Profile.
  3. Fill in your full address, city, state, country, and phone number — all fields must be complete.
  4. Look for a Trade Compliance section or link in your profile. Fill out the short export compliance questionnaire. This is a US government requirement Broadcom enforces for all downloads.
  5. Save your profile. Downloads should now unlock on the next page load.
Part 2 — Download VMware Fusion Pro
  1. Go to vmware.com/products/desktop-hypervisor/workstation-and-fusion and click "Download Now" (the general button — not a Mac-specific link).
  2. You'll be redirected to the Broadcom downloads page. Click the link labelled "Free Software Downloads available HERE", which takes you to support.broadcom.com/group/ecx/free-downloads.
  3. Select VMware Fusion → select the latest release (currently VMware Fusion 26H1 or similar year-based label) → choose the latest release version.
  4. Click the Terms and Conditions link — this opens the agreement in a new tab. Review it, then close that tab and return to the download page.
  5. Back on the download page, check the terms acceptance checkbox (it only activates after you've visited the agreement link) → click Download.
  6. The .dmg installer downloads (~600 MB).
Part 3 — Install on your Mac
  1. Open the downloaded .dmg and drag VMware Fusion to your Applications folder.
  2. Launch it from Applications. It will prompt for your system password to install a kernel extension.
  3. Open System Settings → Privacy & Security → Accessibility and toggle VMware Fusion on. Restart your Mac if prompted.
  4. When VMware asks for a license key, select the option for personal/free use (exact wording varies by version). No key needed.

Step 02

Get the Windows 11 ARM64 ISO

Microsoft's standard download page only serves x86-64 ISOs — you cannot download an ARM64 image from there. UIC students have a simpler option: the UIC IT webstore provides a properly licensed ARM64 ISO directly. Use that if you're a UIC student; the other methods are fallbacks.

Method A — UIC IT Webstore (UIC Students — Recommended)
  1. Go to webstore.illinois.edu/shop/product.aspx?zpid=1288 and sign in with your UIC NetID.
  2. Download "Windows 11 25H2 Arm64" (or the latest Arm64 version listed). This is a fully licensed ISO under UIC's Microsoft campus agreement — no workarounds needed.
  3. Save the .iso somewhere easy to find (e.g. your Desktop or Downloads folder).
Method B — UUP Dump (Non-UIC or fallback)
  1. Go to uupdump.net.
  2. In the search box, type "Windows 11" and press Enter. When results appear, open the Architecture filter and select arm64. Do not use the "Latest Dev/Beta channel" shortcut — those are pre-release builds and can cause instability under a VM.
  3. From the filtered results, pick the newest stable public release (look for a build labelled with the current GA version, e.g. 25H2 or later — avoid anything marked Dev, Beta, or Canary).
  4. Click Next → choose your language → select Windows 11 Pro (recommended over Home).
  5. On the download options screen:
    • Download method: select "Download and convert to ISO"
    • Conversion options: uncheck "Include updates" (it says "Windows converter only" — it will block the macOS script). Leave all other options unchecked.
  6. Click "Create download package." You'll download a small .zip (~1 MB).
  7. ⚠ Before proceeding: check whether the summary panel on the right shows a warning that says "Windows is required to create the ISO image." If it does, skip to Method B — the macOS script will not work for that build, and Method B is simpler anyway.
  8. If no Windows warning appears: extract the .zip and run in Terminal:
    macOS Terminal
    chmod +x uup_download_macos.sh
bash uup_download_macos.sh
  9. The script downloads components from Microsoft's servers and builds the ISO (~5 GB, takes 20–40 minutes). The finished .iso appears in the same folder.
Method C — Windows Insider Program (fallback if UUP Dump shows a Windows-required warning)
  1. Sign in or sign up at insider.windows.com with a free Microsoft account.
  2. Go to insider.windows.com/en-us/getting-started#install and scroll to the ISO download section.
  3. Under edition, select Windows 11 Client ARM64 and choose the Release Preview channel (most stable Insider option). Select your language and click Confirm.
  4. Download the ISO (~5–6 GB) directly — no scripts or conversion needed.
⚠
Do not use a standard x86-64 Windows ISO. VMware Fusion on Apple Silicon will not boot it. You need the ARM64 build specifically. Double-check the filename — it should contain "ARM64" or "arm64."
ℹ
If the UUP Dump script fails with a permission error, ensure Xcode Command Line Tools are installed: run xcode-select --install in Terminal first.

Step 03

Create the Virtual Machine

Configure the VM with enough resources for SolidWorks while leaving headroom for macOS. With 16 GB total RAM, 8 GB to the VM is the practical balance — enough for SolidWorks to run, enough left over for macOS to stay responsive.

  1. Open VMware Fusion Pro.
  2. Go to File → New (or click "+" in the VM library).
  3. Select "Install from disc or image" and drag in your Windows 11 ARM64 ISO. Click Continue.
  4. VMware shows a "Choose Firmware Type" screen. Leave it on UEFI (already selected — Windows 11 requires it). Leave "UEFI Secure Boot" unchecked — enabling it can block VM drivers and isn't needed here. Click Continue.
  5. VMware shows a "Choose Encryption" screen. Windows 11 requires a virtual TPM, which needs some VM files to be encrypted. Leave the selection on "Only the files needed to support a TPM are encrypted" (the default). Click "Auto Generate Password" — leave "Remember Password and store it in Mac's Keychain" checked so macOS handles it automatically. Click Continue.
  6. VMware should auto-detect "Windows 11 ARM 64-bit." If not, set it manually from the dropdown.
  7. Click "Customize Settings" — VMware will first prompt you to name and save the VM file (e.g., "Windows 11 ARM"). After saving, the settings panel opens automatically. If it doesn't, right-click the VM in the library → Settings, or go to Virtual Machine → Settings from the menu bar.
  8. Do not start the VM yet. Apply all settings below first — particularly 3D graphics, which must be enabled before Windows boots for the first time.

Apply these settings in the VM settings panel:

Memory (RAM)8192 MB8 GB is the sweet spot on 16 GB total — leaves macOS 8 GB to stay responsive. 10 GB is possible but can starve macOS.

⚠
"Accelerate 3D Graphics" must be enabled (found under the Display section of VM settings). Without it, SolidWorks will not open at all — even after the OpenGL registry fix in Step 8. Enable it before first boot.

Step 04

Install Windows 11 ARM

The Windows 11 setup process has a few gotchas on a fresh VM, particularly around Microsoft's forced account sign-in. Follow these steps to get a clean local account install.

  1. Start the VM. When you see "Press any key to boot from CD or DVD…" click inside the VM window and press any key immediately.
  2. The Windows Setup wizard loads. Choose your language and keyboard layout → click Install Now.
  3. When asked for a product key, click "I don't have a product key."
  4. Select Windows 11 Pro as the edition → click Next.
  5. Accept the license terms → select "Custom: Install Windows only (advanced)".
  6. Select the unallocated disk space → click Next. Windows installs and restarts several times automatically (~15–20 min).
Bypass the Network & Microsoft Account Requirement

Windows 11 blocks setup at the network screen and hides the "skip" option until you run a bypass command. The "Next" button will be greyed out — do not try to install a driver. Use the command below instead:

  1. When setup shows the "Let's connect you to a network" screen (Next is greyed out), click inside the VM window to give it focus, then press Fn + Shift + F10 to open a Command Prompt. (On Mac, F-keys default to media controls — Fn is required to send the actual F10 key to Windows. If it still opens a Mac app, try pressing Control + Command + G first to fully capture your keyboard into the VM, then retry Fn + Shift + F10.)
  2. Type the following and press Enter:
    Windows CMD (inside VM)
    OOBE\BYPASSNRO
  3. The VM restarts automatically and returns to the network screen. This time you will see "I don't have internet" at the bottom — click it.
  4. Windows may show a "Continue with limited setup" screen — click it if present. On some builds this screen is skipped entirely.
  5. Enter a local username and password, then answer the security questions (used for local password recovery). Complete any remaining prompts. You now have a local Windows account with no Microsoft account required.

Step 05

Post-Install: VMware Tools & Windows Updates

Before installing SolidWorks, get the VM into a clean, fully updated state. VMware Tools installs the display drivers, clipboard sharing, and drag-and-drop that make the VM usable.

Install VMware Tools
  1. In the VMware Fusion menu bar: Virtual Machine → Install VMware Tools. A virtual DVD mounts inside Windows.
  2. Open File Explorer → navigate to the mounted drive (usually D:).
  3. Run setup.exe (or setup64.exe). Choose Complete installation → click through the wizard → Finish.
  4. Restart the VM when prompted.
Install All Windows Updates
  1. Go to Settings → Windows Update → Check for Updates.
  2. Install all available updates including optional ones. Restart when prompted.
  3. Repeat until the screen shows "You're up to date." This typically takes 2–3 rounds.
Install Visual C++ Redistributables
  1. Inside the VM, open a browser and search "Visual C++ Redistributable latest" on Google — the first result is usually the Microsoft Learn page. The direct URL is learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist. Do not try to navigate microsoft.com directly; it's difficult to find the right page from there.
  2. On that page, download and install both: vc_redist.x64.exe and vc_redist.x86.exe (the 2015–2022 versions). SolidWorks is a 32-bit application running on a 64-bit OS, so both are required.
  3. Restart the VM once more after installing.
ℹ
All downloads and installs from this point forward happen inside the Windows VM, not on your Mac. Open the browser inside the VM for everything SolidWorks-related.

Step 07

Install SolidWorks

Run the Installation Manager inside the Windows VM. Budget 45–90 minutes depending on your internet speed and the components you select. The VM must stay online throughout.

  1. Right-click the SolidWorks Installation Manager executable → Run as administrator.
  2. A WinZip Self-Extractor dialog appears (titled something like SolidWorksSetup2026_2027_SP2_...). The default settings are correct — leave both checkboxes checked ("Overwrite files without prompting" and "When done unzipping open: sldim\sldim.exe"). Click "Unzip" and wait for extraction to complete. The Installation Manager (sldim.exe) launches automatically when done.
  3. Select "Install on this computer" → click Next.
  4. Enter your serial number in the 3D Design field. Leave all other serial number fields blank.
  5. Click Next. The manager verifies your serial number against Dassault's servers — the VM must be online (NAT networking).
  6. You'll see a warning about unsupported graphics. This is expected and safe to dismiss. The OpenGL fix in Step 8 addresses it.

Step 08

Activate Your License

On first launch, SolidWorks immediately prompts for license activation. Complete this before applying the OpenGL fix — the app will be slow at this stage, which is expected. This first launch also creates the registry keys needed in Step 9.

  1. Launch SolidWorks from the Start menu or desktop shortcut.
  2. When the Product Activation dialog appears, select "Activate automatically over the internet."
  3. Confirm your serial number is pre-filled. If not, enter it now.
  4. Click Activate. SolidWorks contacts Dassault's servers. Ensure the VM is online (NAT network).
  5. On success, click Finish. SolidWorks opens to the welcome screen — it will be very slow and sluggish without the OpenGL fix. This is normal.
  6. Close SolidWorks and proceed to Step 9.
If Your School Uses a Network License Server (SNL)
  1. Get the license server hostname or IP address from your department's IT.
  2. In SolidWorks: Tools → Options → System Options → General → Specify License Server.
  3. Enter the server address. The VM must be on the same network — from home, your campus VPN is likely required.

Step 09

OpenGL Registry Fix (Skip for SW 2026)

This fix was required for SolidWorks 2020–2025 on VMware/ARM. SolidWorks 2026 does not need it. SW 2026 automatically detects that the VMware virtual GPU is not a certified card and locks itself into Software OpenGL mode — you can confirm this yourself: in SolidWorks, go to Tools → Options → System Options → Performance and look for "Use Software OpenGL." In SW 2026 on VMware it will be checked and grayed out, meaning SolidWorks chose software rendering automatically and the option cannot be toggled. The registry path Performance\Graphics that this fix targets does not exist in SW 2026 because the app no longer uses it.

✓
If you are running SolidWorks 2026: skip this step entirely. The "Use Software OpenGL — checked and grayed out" state in Tools → Options → System Options → Performance is expected and correct. SolidWorks is running and will remain stable without any registry edits.
ℹ
What software OpenGL means for performance. Software OpenGL means all viewport rendering is done by the CPU, not the GPU. This is why the viewport can feel sluggish during model rotation and rebuilds — the rendering bottleneck is structural, not a misconfiguration. Reduce it with the SolidWorks performance settings in Step 10.

The steps below are preserved for users on SolidWorks 2020–2025 who encounter crashes or a black viewport. If you are on SW 2026, stop here.

⚠
SW 2020–2025 only — You must have completed Step 8 (activation) before this step. That first launch creates the registry keys you'll edit here. Replace 20XX in all paths below with your installed version year.
Open Registry Editor
  1. Press Win + R, type regedit, press Enter. Accept the UAC prompt.
Part 1 — Edit the "Current" Graphics Key
  1. Navigate to: HKEY_CURRENT_USER\Software\SolidWorks\SOLIDWORKS 20XX\Performance\Graphics\Hardware\Current
  2. In the right panel, find the Renderer string value. Note the exact text — something like VMware, Inc. SVGA3D. Copy it exactly, character for character.
  3. Find the Workarounds DWORD → double-click it → set the base to Hexadecimal → enter value 4000480 → OK.
Part 2 — Create a Renderer Profile Under Gl2Shaders
  1. Navigate to: HKEY_CURRENT_USER\Software\SolidWorks\SOLIDWORKS 20XX\Performance\Graphics\Hardware\Gl2Shaders\Other
  2. Right-click in the left (key tree) panel → New → Key.
  3. Name the new key exactly as your Renderer string from Part 1 (e.g., VMware, Inc. SVGA3D).
  4. Click into the new key. Right-click in the right panel → New → DWORD (32-bit) Value → name it Workarounds.
  5. Double-click the new Workarounds DWORD → set base to Hexadecimal → enter 40000 → OK.
Part 3 — Edit the VMware Vendor Key
  1. Navigate to: HKEY_CURRENT_USER\Software\SolidWorks\SOLIDWORKS 20XX\Performance\Graphics\Hardware\VMware, Inc.
  2. If this key doesn't exist, create it: navigate to ...Hardware\ → right-click → New → Key → name it VMware, Inc.
  3. Find or create a Workarounds DWORD. Set it to 4000480 (Hexadecimal).
  4. If a sub-key exists inside VMware, Inc. (e.g., Gallium or SVGA3D), open it and set its Workarounds DWORD to 4000480 as well.
✓
Restart Windows fully after completing all three parts — not just SolidWorks, the entire VM. Registry changes take effect on the next Windows boot.
ℹ
All values must be entered in Hexadecimal. When the DWORD editor opens, select "Hexadecimal" before typing. The value 4000480 in hex is 67,109,504 in decimal — entering the wrong base produces a completely different value that won't work.

Step 10

Verify the Installation

Run through this checklist to confirm SolidWorks is working before relying on it for coursework.

  1. Open a new Part file: File → New → Part → OK. The part modeling environment should open without errors or crashes.
  2. Create a sketch: Click the Front Plane in the feature tree → Insert Sketch. Draw a rectangle using the corner rectangle tool.
  3. Extrude it: Exit the sketch → Features tab → Extruded Boss/Base → set depth to 25 mm → click the green checkmark. A 3D solid should appear.
  4. Rotate the model: Hold the middle mouse button and drag. Model rotation should be smooth and responsive.
  5. Check RealView: View → Display → RealView Graphics. If it is greyed out, that is expected and normal on this hardware configuration — it does not affect modeling functionality.
  6. Save a file: File → Save → save the part to the Desktop inside Windows. Confirm it saves without error.
✓
If you can create a part, extrude it, rotate the 3D view, and save — the installation is working correctly. RealView being unavailable is a cosmetic limitation only. Core modeling is fully functional.
Reduce Rendering Slowness — SolidWorks Settings

All of these are inside SolidWorks (not VMware or Windows). Apply them in order — the Display settings have the most noticeable impact on day-to-day interaction.

Tools → Options → System Options → Display (do these first)

  1. In SolidWorks: Tools → Options → System Options → Display.
  2. Uncheck "Dynamic highlight from graphics card" — this is the most impactful setting. When on, SolidWorks animates selection highlights (e.g., the orange outline that draws around a plane before your click registers) through the software OpenGL stack, blocking input until the animation finishes. Turning it off gives an immediate, non-animated highlight instead.
  3. Uncheck "Shadows in Shaded Mode" if enabled.
  4. Uncheck "Ambient Occlusion" if present and enabled.
  5. Click OK.

Tools → Options → System Options → Performance

  1. In SolidWorks: Tools → Options → System Options → Performance.
  2. Drag "Image quality for shaded and draft quality HLR/HLV" slider all the way left.
  3. Reduce Level of detail if the option is available.
  4. Click OK.
✓
Normal To without touching the viewport: click the plane's name in the Feature Tree (the left sidebar — "Top Plane", "Front Plane", etc.) rather than clicking the plane geometry in the 3D view. Feature Tree selection is a list operation — no OpenGL rendering, no orange animation. Then press Ctrl+8 to snap Normal To. This is the fastest path on this hardware setup.
⚠
Known limitation — no fix found yet for SW 2026 on M2. When hovering over or clicking a reference plane in the viewport, SolidWorks animates an orange rectangle that draws out fully before your input is registered. This is a consequence of software OpenGL rendering every stroke of that outline on the CPU — there is currently no setting or registry edit known to eliminate it on SolidWorks 2026 running under VMware Fusion on Apple Silicon.

Workarounds: Select planes from the Feature Tree (left sidebar) rather than clicking them in the viewport — no animation, instant selection. Press Ctrl+8 after selecting to go Normal To. To remove planes from the viewport entirely: View → Hide/Show → Planes.

If you find a fix, please contribute it — open an issue or pull request on the GitHub repository for this guide. Any validated solution (registry edit, VMware setting, SolidWorks option) will be documented here with credit.

Advanced: Try unlocking hardware OpenGL via VMware settings

SolidWorks forces software OpenGL because VMware's virtual GPU (SVGA3D, backed by Metal on Apple Silicon) is not on Dassault's certified hardware list. A VMware configuration flag may change how the GPU is presented to the guest and allow SolidWorks to use hardware rendering instead. This is not guaranteed to work on Apple Silicon — try it and check Tools → Options → System Options → Performance to see if "Use Software OpenGL" becomes unchecked and unlocked.

  1. Shut down the Windows VM completely and then quit VMware Fusion entirely (⌘+Q, not just close the window).
  2. On your Mac, open Terminal (Spotlight → Terminal).
  3. Run this command to add the flag to VMware's global preferences: echo 'mks.gl.allowBlacklistedDrivers = "TRUE"' >> ~/Library/Preferences/VMware/preferences.ini
  4. Reopen VMware Fusion → start the VM → launch SolidWorks.
  5. In SolidWorks: Tools → Options → System Options → Performance. If "Use Software OpenGL" is now unchecked and not grayed out, hardware rendering is active — the viewport will feel noticeably more responsive.
  6. If there is no change, the setting had no effect on this hardware configuration. You can remove the line by opening ~/Library/Preferences/VMware/preferences.ini in TextEdit and deleting it.
⚠
Do not use mks.enableMTLRenderer = "FALSE" — this disables Apple Metal, which is the entire graphics stack on Apple Silicon. On M2, disabling Metal breaks 3D graphics in the VM entirely. Ignore any guide that recommends this setting for M1/M2 Macs.
ℹ
Why it's still slow even after tuning. VMware Fusion on Apple Silicon uses Metal (Apple's GPU API) for host-side rendering and exposes it to the guest as an SVGA3D virtual GPU with OpenGL 4.2. SolidWorks doesn't recognize SVGA3D as a certified workstation GPU and forces software rendering. Every graphics call passes through: SolidWorks software OpenGL → x86 emulation → ARM virtualization → Metal → M2 silicon. This chain is structural. Light parts and individual assemblies are workable; heavy simulation and large assemblies belong on a campus workstation.

Troubleshooting

"vc_redist.x64.exe did not install successfully" during Installation Manager
Two related errors can appear here — both are harmless:

1. "vc_redist.x64.exe did not install successfully" — the silent install flag failed. Click OK; the Installation Manager usually continues anyway.

2. "Setup Failed — 0x80070666 — Another version of this product is already installed" — this means a newer version of the Visual C++ Redistributable is already on the system. Do not uninstall anything. Click Close — the requirement is already satisfied and SolidWorks will install fine.

In both cases, simply dismiss the dialog and allow the Installation Manager to continue. Only if SolidWorks later fails to launch should you manually install the redistributable: navigate to ...\SOLIDWORKS 2026 SP02.1\PreReqs\VCRedist17\ and run vc_redist.x64.exe and vc_redist.x86.exe directly.
SolidWorks shows a black screen or crashes immediately on launch
SolidWorks 2026: the registry fix is not used by SW 2026 — a black screen is more likely a Display settings issue. Confirm "Accelerate 3D Graphics" is enabled in VMware Fusion → VM Settings → Display. Restart the VM fully and try again.

SolidWorks 2020–2025: almost always the registry fix. Verify: (a) you launched SolidWorks at least once before editing the registry so the keys exist; (b) all Workarounds DWORD values were entered with the base set to Hexadecimal, not Decimal; (c) "Accelerate 3D Graphics" is enabled in VMware settings. Restart Windows completely after making registry changes.
"Graphics card not supported" warning appears on every launch
Expected behavior — SolidWorks does not recognize VMware's virtual GPU as a certified workstation card. Click OK to dismiss. To suppress it permanently: Tools → Options → System Options → Messages/Errors/Warnings → find the graphics message and hide it.
License activation fails with a network or connection error
Confirm the VM's network adapter is set to NAT in VMware Fusion settings (not Host-Only or Bridged). NAT shares your Mac's network connection with the VM. If the VM can browse the web but activation still fails, Dassault's activation servers may be temporarily unavailable — wait an hour and try again.
VMware Fusion won't start — shows "kernel extension blocked"
Go to System Settings → Privacy & Security on your Mac, scroll down, and click Allow next to the VMware system extension. A Mac restart is typically required after approving. This is a macOS security requirement enforced for all third-party kernel extensions.
The registry key path Gl2Shaders\Other doesn't exist
The full key tree only populates after SolidWorks runs at least once. If Gl2Shaders or Other are missing as keys, create them manually: right-click the parent key → New → Key → name it exactly. Then create sub-keys as described in Step 8.
Selecting a plane or face animates slowly — orange outline draws out fully before input registers
No complete fix is currently known for SolidWorks 2026 on VMware/M2. Two separate effects are at play:

Hover highlight (before clicking): try Tools → Options → System Options → Display → uncheck "Dynamic highlight from graphics card". This may reduce the animated hover effect.

Selection visualization (orange rectangle after clicking in the viewport): rendered stroke by stroke on the CPU in software OpenGL mode. No setting or registry edit has been found to eliminate this on SW 2026 + VMware Fusion + Apple Silicon. VMware's mks.gl.allowBlacklistedDrivers flag and the global preferences.ini approach were tested and did not resolve it.

Best workaround: select planes from the Feature Tree (left sidebar) — no animation, instant selection. Then press Ctrl+8 for Normal To. To hide planes from the viewport entirely: View → Hide/Show → Planes.

If you find a fix, open an issue or pull request on the guide's GitHub repository so it can be documented here.
SolidWorks runs but feels very sluggish
There are several layers to address:

1. SolidWorks internal settings (most impactful): In SolidWorks — Tools → Options → System Options → Performance. Drag the image quality slider left and reduce level of detail. Under Display, turn off anti-aliasing. These lower the rendering load on the emulated GPU.

2. Check macOS memory pressure: On your Mac, open Activity Monitor (Spotlight → "Activity Monitor") → click the Memory tab → look at the memory pressure bar at the bottom. If it is yellow or red, macOS is swapping and the VM is being starved regardless of how much you allocated. Close unused Mac apps.

3. VM resource balance: With 16 GB total RAM, giving the VM 10 GB leaves macOS only 6 GB — which can cause the host to page and slow everything down. 8 GB for the VM is usually the better balance. In VMware Fusion, shut down the VM, then go to VM Settings → Processors & Memory and adjust.

4. Structural limitation: SolidWorks (x86) → Windows ARM emulates x86 → M2 runs ARM. Every instruction passes through two translation layers. No amount of tuning fully removes this overhead. Heavy simulation and rendering belong on a campus workstation.
The UUP Dump shell script fails on macOS
Make the script executable first with chmod +x uup_download_macos.sh, then run it with bash uup_download_macos.sh. If it still fails, install Xcode Command Line Tools: xcode-select --install in Terminal, then retry the script.
OOBE\BYPASSNRO command isn't available or doesn't work
An alternative bypass: when on the Microsoft sign-in screen during setup, press Shift+F10 to open CMD, then run ipconfig /release to cut the network connection. Setup will then offer a "Sign in later" or offline account path. Reconnect the VM network (Virtual Machine → Network Adapter → NAT) after Windows finishes setup.
